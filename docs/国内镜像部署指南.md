# 国内镜像部署指南（解决 GitHub Pages 国内访问受限）

本系统主站托管在 **GitHub Pages**（`https://liening1.github.io/huangdi-algae-monitor/`）。
由于 GitHub 的 CDN 在国内经常被限速或间歇性阻断，国内用户可能出现「地图一直转圈 / 数据加载不出来」。

本指南提供两套互补方案：

1. **前端自动提示切换**（已内置）：国内访问慢时，页面顶部弹出「切换到国内镜像」横幅，一键跳转。
2. **部署一个国内镜像站点**（本文档）：把同一套静态文件同步到 EdgeOne Makers（腾讯云），国内可直连、免费、无需 ICP 备案。

---

## 一、前置：激活前端镜像提示

前端代码已写好，只需在 `web/static/app.js` 顶部把镜像地址填进去即可生效：

```js
// web/static/app.js
const CN_MIRROR = "";   // ← 改成你的 EdgeOne Makers 域名，例如：
// const CN_MIRROR = "https://huangdi-algae-monitor.edgeone.app/";
```

填好后随每日流水线自动部署。效果：
- 在 GitHub 原站：探测 `outputs/manifest.json` 延迟，超过 4.5s 或失败时弹出横幅 + 底部常驻链接；
- 在镜像站：自动显示「返回 GitHub 原站」入口，不再探测；
- 支持 `?cn=1` / `?cn=0` 强制选择，记忆到 `localStorage`。

## 二、关于 cnb.cool 与 Coding 的说明（重要）

- **Coding DevOps 已暂停注册**（官方公告），原 Coding Pages 路线走不通。
- **cnb.cool** 是腾讯云下一代代码托管 + 云原生构建（CI）平台，但它**本身不直接托管静态网站**。其推荐的静态托管链路是 `cnb.cool 仓库 → .cnb.yml 构建 → edgeone makers deploy → EdgeOne Makers`。因此「用 cnb.cool 做镜像」的真实形态就是 **EdgeOne Makers**。

本系统**不需要把代码搬迁到 cnb.cool**，直接用 EdgeOne Makers 的「direct upload（直接上传）」能力即可，链路更简单。

---

## 三、方案 A（推荐）：EdgeOne Makers（腾讯云）

EdgeOne Makers 是腾讯云边缘安全加速平台的静态托管服务（类似 Cloudflare Pages），**国内访问速度极佳**，最贴近「国产化、稳定直连」诉求。免费、默认域名由控制台分配、无需备案即可用。

> ⚠️ 前置条件：**需要腾讯云账号 + 实名认证**（腾讯系，审核通常比 Gitee 快）。

### 步骤
1. 注册/登录 [腾讯云](https://cloud.tencent.com) 并完成实名认证。
2. 进入 **EdgeOne → Makers**（或 EdgeOne Pages）控制台，新建项目，**类型务必选「直接上传 / Direct Upload」**（CLI 部署要求目标为 direct upload 类型），记下「项目名称」。
3. 在控制台生成 **API Token**（Makers/EdgeOne 的 API Token，用于 CI/无头部署），复制保存。
4. 本地部署站点（推荐，不必接入 cnb.cool CI）：
   - 准备部署目录：把 `gh-pages` 分支内容导出到本地目录（如 `./dist`）；
   - 执行 EdgeOne CLI 上传（**注意：新版 CLI 用 `makers` 子命令，`pages` 已弃用**）：
     ```bash
     npx edgeone makers deploy ./dist -n <项目名称> -t <API Token> -a global
     ```
     - `-n` 项目名（不存在则自动创建，存在则更新；要求为 direct upload 类型）
     - `-t` API Token（无头/CI 环境必填）
     - `-a global` 部署到国内/全球节点；`-e production` 为默认环境
   - 也可用仓库自带脚本：`EDGEONE_TOKEN=xxx EDGEONE_PROJECT=xxx bash scripts/edgeone-deploy.sh`（自动拉取最新 gh-pages 并上传）。
5. 部署成功后，控制台会显示该项目访问域名（Makers 默认域名形如 `https://<项目名>.edgeone.app/`，**以控制台实际显示为准**，并非 `*.pages.dev`）。可后续在控制台绑定自定义域名。

### 填 CN_MIRROR
把上一步控制台显示的域名填入 `app.js` 的 `CN_MIRROR` 并提交推送，前端切换提示随即生效。

### 大小限制核对 ✅
EdgeOne 对单文件通常限制约 25MB。已核对本仓库 `gh-pages`：**不存在任何 >25MB 的文件**，单文件限制不是障碍。
但 **181MB 总体积** 是否落在免费额度内，需在首次部署时实测确认；若超限再改用「六、进阶」里的 COS+CDN 方案。

## 四、方案 B（备选）：Gitee Pages（码云）

Gitee Pages 国内访问稳定，但**免费版不会在 push 后自动部署，且需先完成实名认证**才会出现入口。适合不追求全自动、愿意偶尔手动更新的场景。

### 步骤
1. 在 [Gitee](https://gitee.com) 新建**公开**仓库，例如 `huangdi-algae-monitor`。
2. 右上角头像 → **账号设置 → 实名认证**（强制门槛，审核 1~3 个工作日）。
3. 生成一个 **Gitee 私人令牌**（权限勾 `projects`）。
4. 把 `gh-pages` 内容推送到 Gitee 仓库（可用 `scripts/mirror.sh`，目标改为 Gitee，部署分支 `master`）。
5. 仓库 → **服务 → Gitee Pages**（实名后才会出现）→ 部署分支选 `master`、目录 `/`、强制 HTTPS → 启动。
   之后每次更新需在 Gitee Pages 页面点「更新」重新部署。

Gitee Pages 地址形如 `https://<用户名>.gitee.io/huangdi-algae-monitor/`。

---

## 五、手动同步脚本

- `scripts/edgeone-deploy.sh`：**EdgeOne Makers 部署**（推荐）。自动拉取最新 `gh-pages` 并 `edgeone makers deploy`：
  ```bash
  EDGEONE_TOKEN=xxxx EDGEONE_PROJECT=huangdi-algae-monitor bash scripts/edgeone-deploy.sh
  ```
- `scripts/mirror.sh`：Gitee / Coding（已弃用）目标的历史脚本，保留备用。

> 注意：`gh-pages` 包含 S2 影像切片等数据，约 180MB，首次上传可能需 1~2 分钟。本地 → 腾讯云链路实测稳定。

## 六、验证清单
- [ ] 国内手机热点 / 宽带能打开镜像域名，地图与数据正常加载；
- [ ] 原站顶部横幅能弹出，点击可跳转镜像；

- [ ] 同步后，镜像数据日期与原站一致（看 Bento 卡片「影像日期」）。

## 七、备选 / 进阶
- **腾讯云 COS + CDN**：若 EdgeOne Makers 免费额度装不下 181MB，或你有已备案域名，可将站点放到 COS 并挂 CDN，速度最佳、可控性最高（需在脚本里把上传步骤换成 `coscli sync`）。
- **CloudStudio 静态托管**：适合临时演示，URL 随工作区生命周期变化，不推荐做长期镜像。
- **多镜像冗余**：可同时部署 EdgeOne + Gitee，前端 `CN_MIRROR` 指向其中一个，另一个作为人工备份。
