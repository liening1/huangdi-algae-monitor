# 国内镜像部署指南（解决 GitHub Pages 国内访问受限）

本系统主站托管在 **GitHub Pages**（`https://liening1.github.io/huangdi-algae-monitor/`）。
由于 GitHub 的 CDN 在国内经常被限速或间歇性阻断，国内用户可能出现「地图一直转圈 / 数据加载不出来」。

本指南提供两套互补方案：

1. **前端自动提示切换**（已内置）：国内访问慢时，页面顶部弹出「切换到国内镜像」横幅，一键跳转。
2. **部署一个国内镜像站点**（本文档）：把同一套静态文件同步到 Coding Pages 或 Gitee Pages，二者在国内均可直连，免费、无需 ICP 备案。

---

## 一、前置：激活前端镜像提示

前端代码已写好，只需在 `web/static/app.js` 顶部把镜像地址填进去即可生效：

```js
// web/static/app.js
const CN_MIRROR = "";   // ← 改成你的国内镜像地址，例如：
// const CN_MIRROR = "https://<你的用户名>.coding.me/huangdi-algae-monitor/";
// const CN_MIRROR = "https://<你的用户名>.gitee.io/huangdi-algae-monitor/";
```

填好后随每日流水线自动部署。效果：
- 在 GitHub 原站：探测 `outputs/manifest.json` 延迟，超过 4.5s 或失败时弹出横幅 + 底部常驻链接；
- 在镜像站：自动显示「返回 GitHub 原站」入口，不再探测；
- 支持 `?cn=1` / `?cn=0` 强制选择，记忆到 `localStorage`。

## 二、方案 A（推荐）：Coding Pages（腾讯云，自动部署）

Coding Pages 在 push 到 `coding-pages` 分支后**自动重新部署**，无需手动点按钮，最适合对接本项目的每日自动流水线。

### 步骤
1. 注册并登录 [Coding.net](https://coding.net)（腾讯云账号可直接登录）。
2. 新建一个**项目**（DevOps 项目），例如 `huangdi-algae-monitor`。
3. 进入项目 → **设置 → 开发者令牌（或访问令牌 Personal Access Token）**，生成一个具有「代码仓库读写」权限的令牌，复制保存（只会显示一次）。
4. 在项目里创建一个分支命名为 **`coding-pages`**（与部署分支名一致）。
5. 进入项目 **持续部署 → 静态 Pages（网站托管）**，绑定刚建的项目与 `coding-pages` 分支，根目录留空（站点在仓库根）。

### 令牌与仓库地址（填入 GitHub Secrets）
- `CODING_REPO`：仓库的 HTTPS 地址（不含令牌），形如
  `e.coding.net/<团队名>/huangdi-algae-monitor/huangdi-algae-monitor.git`
- `CODING_TOKEN`：第 3 步生成的访问令牌
- （若 Coding 要求用户名+令牌组合鉴权，把 `CODING_REPO` 写成含用户名的形式，或在 `mirror.yml` 中按需调整）

### 自动同步
本仓库已附带 `.github/workflows/mirror.yml`（默认被 `if: secrets.CODING_TOKEN != ''` 门控，未配置前不会运行）。配置好上面两个 Secret 后，它会在每日主站重建后把 `gh-pages` 分支的内容强制推送至 Coding 的 `coding-pages` 分支，实现**全自动镜像**。也可在 Actions 页面手动 `Run workflow` 立即同步。

## 三、方案 B：Gitee Pages（码云）

Gitee Pages 国内访问稳定，但**免费版不会在 push 后自动部署**，需要手动点「更新」或使用 Gitee Pages Pro。适合不追求全自动、愿意偶尔手动更新的场景。

### 步骤
1. 在 [Gitee](https://gitee.com) 新建仓库，例如 `huangdi-algae-monitor`。
2. 生成一个 **Gitee 私人令牌（Private Token）**。
3. 把 `gh-pages` 内容推送到 Gitee 仓库（可用 `scripts/mirror.sh`，把目标改为 Gitee）。
4. 仓库 → **服务 → Gitee Pages** → 部署分支选你推送的分支 → 启动。
   之后每次更新需在 Gitee Pages 页面点「更新」重新部署（或升级 Pro 实现自动）。

Gitee Pages 地址形如 `https://<用户名>.gitee.io/huangdi-algae-monitor/`。

## 四、手动同步脚本 `scripts/mirror.sh`

适用于本地一次性推送，或临时替代 CI：

```bash
# 用法（需 git 与网络）：
#   CODING_TOKEN=xxxx CODING_REPO=e.coding.net/.../huangdi.git bash scripts/mirror.sh
#   GITEE_TOKEN=xxxx GITEE_REPO=gitee.com/.../huangdi.git bash scripts/mirror.sh
```

脚本会：克隆本仓库 `gh-pages` 分支（已构建好的站点）→ 重新初始化为静态根 → 强推到目标仓库的部署分支。

> 注意：`gh-pages` 包含 S2 影像切片等数据，体积较大，首次推送可能需数分钟。

## 五、验证清单
- [ ] 国内手机热点 / 宽带能打开镜像地址，地图与数据正常加载；
- [ ] 原站顶部横幅能弹出，点击可跳转镜像；
- [ ] 镜像站底部显示「返回 GitHub 原站」；
- [ ] 每日自动同步后，镜像数据日期与原站一致（看 Bento 卡片「影像日期」）。

---

## 六、备选 / 进阶
- **腾讯云 COS + CDN**：若你有已备案域名，可将站点放到 COS 并挂 CDN，速度最佳、可控性最高（需在 `mirror.yml` 里把推送步骤换成 `coscli sync`）。
- **CloudStudio 静态托管**：适合临时演示，URL 随工作区生命周期变化，不推荐做长期镜像。
- **多镜像冗余**：可同时部署 Coding + Gitee，前端 `CN_MIRROR` 指向其中一个，另一个作为人工备份。
