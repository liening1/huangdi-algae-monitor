# 国内镜像部署指南（解决 GitHub Pages 国内访问受限）

本系统主站托管在 **GitHub Pages**（`https://liening1.github.io/huangdi-algae-monitor/`）。
由于 GitHub 的 CDN 在国内经常被限速或间歇性阻断，国内用户可能出现「地图一直转圈 / 数据加载不出来」。

本指南提供两套互补方案：

1. **前端自动提示切换**（已内置）：国内访问慢时，页面顶部弹出「切换到国内镜像」横幅，一键跳转。
2. **部署一个国内镜像站点**（本文档）：把同一套静态文件同步到 Coding Pages（腾讯云），国内可直连，免费、无需 ICP 备案。

---

## 一、前置：激活前端镜像提示

前端代码已写好，只需在 `web/static/app.js` 顶部把镜像地址填进去即可生效：

```js
// web/static/app.js
const CN_MIRROR = "";   // ← 改成你的 Coding Pages 地址，例如：
// const CN_MIRROR = "https://xxxx.coding-pages.com/";
```

填好后随每日流水线自动部署。效果：
- 在 GitHub 原站：探测 `outputs/manifest.json` 延迟，超过 4.5s 或失败时弹出横幅 + 底部常驻链接；
- 在镜像站：自动显示「返回 GitHub 原站」入口，不再探测；
- 支持 `?cn=1` / `?cn=0` 强制选择，记忆到 `localStorage`。

## 二、方案 A（推荐，已采用）：Coding Pages（腾讯云）

Coding Pages（腾讯云开发者平台）国内访问稳定，**持续部署会自动监听分支 push 并重新部署**，最适合对接本项目的每日自动流水线。

> ⚠️ 当前版本（2025 起）的注意事项：
> - 静态网站入口为 **持续部署 → 静态网站**（旧版「Pages 服务」已合并/更名）。
> - 分配的默认域名为 `https://<随机串>.coding-pages.com`（旧版 `xxx.coding.me` 已弃用）。
> - 静态网站服务**可能要求实名认证**（腾讯系，通常审核较快）。

### 步骤
1. 注册并登录 [Coding.net](https://coding.net)（腾讯云账号可直接登录，建议用微信/QQ/手机号）。
2. 新建一个 **DevOps 项目**（项目名称任意，例如 `huangdi-algae-monitor`）。
3. 进入项目 → **代码仓库**，新建一个代码仓库（启用 README 初始化，让仓库先有默认分支）。
4. 生成访问令牌：右上角头像 → **个人设置 → 访问令牌** → 新建，权限勾选 **`project:depot`（代码仓库读写）**，其余不勾。生成后**立即复制保存「令牌」和页面显示的「令牌用户名」**（都只显示一次）。
5. 开启静态网站：项目左侧 **持续部署 → 静态网站 → 新建网站**，填写网站名，选择第 3 步的仓库、部署分支 **`coding-pages`**、部署路径 **`/`**（站点在仓库根），选择节点后确定发布。发布成功后得到默认地址 `https://<随机串>.coding-pages.com/`。

### 令牌与仓库地址（填入 GitHub Secrets 或本地脚本）
- `CODING_REPO`：代码仓库的 HTTPS 地址（不含令牌），形如
  `e.coding.net/<团队名>/<项目名>/<仓库名>.git`
- `CODING_TOKEN`：第 4 步生成的访问令牌
- 鉴权格式为 `https://<令牌用户名>:<令牌>@e.coding.net/...`（Coding 要求用户名+令牌组合，单用令牌会 401）

### 自动同步
本仓库已附带 `.github/workflows/mirror.yml`，默认把 `gh-pages`（已构建站点）强推到 Coding 的 `coding-pages` 分支，配置好 Secret 后**每日主站重建后自动镜像**。也可在 Actions 页面手动 `Run workflow` 立即同步。

> ⚠️ 实测提示：GitHub Actions 运行器 → Coding 的跨境链路偶尔会卡顿（类似 Gitee）。若自动同步偶发失败，可用 `scripts/mirror.sh` 从本地直推（本地 → Coding 链路实测稳定），不影响已上线的镜像站点。

## 三、方案 B（备选）：Gitee Pages（码云）

Gitee Pages 国内访问稳定，但**免费版不会在 push 后自动部署，且需先完成实名认证**才会出现入口。适合不追求全自动、愿意偶尔手动更新的场景。

### 步骤
1. 在 [Gitee](https://gitee.com) 新建**公开**仓库，例如 `huangdi-algae-monitor`。
2. 右上角头像 → **账号设置 → 实名认证**（强制门槛，审核 1~3 个工作日）。
3. 生成一个 **Gitee 私人令牌**（权限勾 `projects`）。
4. 把 `gh-pages` 内容推送到 Gitee 仓库（可用 `scripts/mirror.sh`，目标改为 Gitee，部署分支 `master`）。
5. 仓库 → **服务 → Gitee Pages**（实名后才会出现）→ 部署分支选 `master`、目录 `/`、强制 HTTPS → 启动。
   之后每次更新需在 Gitee Pages 页面点「更新」重新部署（或升级 Pro 实现自动）。

Gitee Pages 地址形如 `https://<用户名>.gitee.io/huangdi-algae-monitor/`。

## 四、手动同步脚本 `scripts/mirror.sh`

适用于本地一次性推送，或临时替代 CI：

```bash
# 用法（需 git 与网络）：
#   CODING_TOKEN=xxxx CODING_REPO=e.coding.net/.../repo.git bash scripts/mirror.sh
#   GITEE_TOKEN=xxxx GITEE_REPO=gitee.com/.../repo.git    bash scripts/mirror.sh
```

脚本会：克隆本仓库 `gh-pages` 分支（已构建好的站点）→ 重新初始化为静态根 → 强推到目标仓库的部署分支（Coding 用 `coding-pages`，Gitee 用 `master`）。

> 注意：`gh-pages` 包含 S2 影像切片等数据，约 180MB，首次推送可能需 1~2 分钟。

## 五、验证清单
- [ ] 国内手机热点 / 宽带能打开镜像地址（`*.coding-pages.com`），地图与数据正常加载；
- [ ] 原站顶部横幅能弹出，点击可跳转镜像；
- [ ] 镜像站底部显示「返回 GitHub 原站」；
- [ ] 每日自动同步 / 手动同步后，镜像数据日期与原站一致（看 Bento 卡片「影像日期」）。

## 六、备选 / 进阶
- **腾讯云 COS + CDN**：若你有已备案域名，可将站点放到 COS 并挂 CDN，速度最佳、可控性最高（需在 `mirror.yml` 里把推送步骤换成 `coscli sync`）。
- **CloudStudio 静态托管**：适合临时演示，URL 随工作区生命周期变化，不推荐做长期镜像。
- **多镜像冗余**：可同时部署 Coding + Gitee，前端 `CN_MIRROR` 指向其中一个，另一个作为人工备份。
