# 国内镜像部署指南（解决 GitHub Pages 国内访问受限）

本系统主站托管在 **GitHub Pages**（`https://liening1.github.io/huangdi-algae-monitor/`）。
由于 GitHub 的 CDN 在国内经常被限速或间歇性阻断，国内用户可能出现「地图一直转圈 / 数据加载不出来」。

本指南提供两套互补方案：

1. **前端自动提示切换**（已内置）：国内访问慢时，页面顶部弹出「切换到国内镜像」横幅，一键跳转。
2. **部署一个国内镜像站点**（本文档）：把同一套静态文件同步到 EdgeOne Pages（腾讯云），国内可直连、免费、默认 `*.pages.dev` 域名、无需 ICP 备案。

---

## 一、前置：激活前端镜像提示

前端代码已写好，只需在 `web/static/app.js` 顶部把镜像地址填进去即可生效：

```js
// web/static/app.js
const CN_MIRROR = "";   // ← 改成你的 EdgeOne Pages 地址，例如：
// const CN_MIRROR = "https://huangdi-algae-monitor.pages.dev/";
```

填好后随每日流水线自动部署。效果：
- 在 GitHub 原站：探测 `outputs/manifest.json` 延迟，超过 4.5s 或失败时弹出横幅 + 底部常驻链接；
- 在镜像站：自动显示「返回 GitHub 原站」入口，不再探测；
- 支持 `?cn=1` / `?cn=0` 强制选择，记忆到 `localStorage`。

---

## 二、关于 cnb.cool 的说明（重要）

官方已公告 **Coding DevOps 暂停注册**，并引导用户迁移到下一代产品 **cnb.cool**。

但必须澄清一个容易误解的点：**cnb.cool 本身并不直接托管静态网站**（不像老的 Coding Pages「推个分支就出站点」）。cnb.cool 是腾讯云的代码托管 + 云原生构建（CI）平台，它推荐的静态托管链路是：

```
cnb.cool 仓库  →  .cnb.yml 云原生构建  →  edgeone pages deploy  →  EdgeOne Pages（*.pages.dev）
```

也就是说，「用 cnb.cool 做镜像」的真实形态仍然是 **EdgeOne Pages**。因此本系统**不需要把代码搬迁到 cnb.cool**，直接用 EdgeOne Pages 的「直接上传」能力即可，链路更简单、改动更小。

---

## 三、方案 A（推荐）：EdgeOne Pages（腾讯云）

EdgeOne Pages 是腾讯云边缘安全加速平台的静态托管服务（类似 Cloudflare Pages），**国内访问速度极佳**，最贴近「国产化、稳定直连」诉求。免费、默认域名 `*.pages.dev`、无需备案即可用。

> ⚠️ 前置条件：**需要腾讯云账号 + 实名认证**（腾讯系，审核通常比 Gitee 快）。

### 步骤
1. 注册/登录 [腾讯云](https://cloud.tencent.com) 并完成实名认证。
2. 进入 **EdgeOne（边缘安全加速）→ Pages** 控制台，新建项目，类型选 **「直接上传 / Direct Upload」**（模板任选，不影响后续），记下「项目名称」。
3. 在 Pages 控制台 → **API Token** 新建一个 Token，复制保存（只显示一次）。
4. 部署站点（本系统推荐「本地上传」，不必接入 cnb.cool CI）：
   - 准备部署目录：把 `gh-pages` 分支内容 checkout 到本地目录（如 `./dist`）；
   - 执行 EdgeOne CLI 上传：
     ```bash
     npx edgeone pages deploy ./dist -n <项目名称> -t <API Token>
     ```
   - （如需自动化，可后续把该命令集成进 `scripts/mirror.sh` 的 EdgeOne 分支，或写 `.cnb.yml` 由 cnb.cool 触发；本系统暂不强制。）
5. 部署成功后拿到地址 `https://<项目名称>.pages.dev/`（可后续在 Pages 控制台绑定自定义域名）。

### 填 CN_MIRROR
把上一步地址填入 `app.js` 的 `CN_MIRROR` 并提交推送，前端切换提示随即生效。

### 大小限制核对 ✅
EdgeOne Pages 对单文件通常限制约 25MB。已核对本仓库 `gh-pages`：**不存在任何 >25MB 的文件**，单文件限制不是障碍。
但 **181MB 总体积** 是否落在免费额度内，需在首次部署时实测确认；若超限再改用「六、进阶」里的 COS+CDN 方案。

## 四、方案 B（备选）：Gitee Pages（码云）

Gitee Pages 国内访问稳定，但**免费版不会在 push 后自动部署，且需先完成实名认证**才会出现入口。适合不追求全自动、愿意偶尔手动更新的场景。

### 步骤
1. 在 [Gitee](https://gitee.com) 新建**公开**仓库，例如 `huangdi-algae-monitor`。
2. 右上角头像 → **账号设置 → 实名认证**（强制门槛，审核 1~3 个工作日）。
3. 生成一个 **Gitee 私人令牌**（权限勾 `projects`）。
4. 把 `gh-pages` 内容推送到 Gitee 仓库（可用 `scripts/mirror.sh`，目标改为 Gitee，部署分支 `master`）。
5. 仓库 → **服务 → Gitee Pages**（实名后才会出现）→ 部署分支选 `master`、目录 `/`、强制 HTTPS → 启动。
   之后每次更新需在 Gitee Pages 页面点「更新」重新部署。

Gitee Pages 地址形如 `https://<用户名>.gitee.io/huangdi-algae-monitor/`。

## 五、手动同步脚本 `scripts/mirror.sh`

适用于本地一次性推送，或临时替代 CI。当前已支持 **Coding（已弃用：注册暂停）/ Gitee / EdgeOne** 三种目标：

```bash
# 用法（需 git 与网络）：
#   GITEE_TOKEN=xxxx GITEE_REPO=gitee.com/.../repo.git    bash scripts/mirror.sh
#   EDGEONE_TOKEN=xxxx EDGEONE_PROJECT=xxx                bash scripts/mirror.sh
```

脚本会：克隆本仓库 `gh-pages` 分支（已构建好的站点）→ 重新初始化为静态根 → 强推/上传到目标。

> 注意：`gh-pages` 包含 S2 影像切片等数据，约 180MB，首次推送/上传可能需 1~2 分钟。本地 → 国内托管（Gitee / 腾讯云）链路实测稳定；GitHub Actions → 国内托管的跨境链路曾出现卡顿，必要时用本地直推。

## 六、验证清单
- [ ] 国内手机热点 / 宽带能打开镜像地址（`*.pages.dev`），地图与数据正常加载；
- [ ] 原站顶部横幅能弹出，点击可跳转镜像；
- [ ] 镜像站底部显示「返回 GitHub 原站」；
- [ ] 同步后，镜像数据日期与原站一致（看 Bento 卡片「影像日期」）。

---

## 七、备选 / 进阶
- **腾讯云 COS + CDN**：若 EdgeOne Pages 免费额度装不下 181MB，或你有已备案域名，可将站点放到 COS 并挂 CDN，速度最佳、可控性最高（需在 `mirror.sh`/`mirror.yml` 里把推送步骤换成 `coscli sync`）。
- **CloudStudio 静态托管**：适合临时演示，URL 随工作区生命周期变化，不推荐做长期镜像。
- **多镜像冗余**：可同时部署 EdgeOne + Gitee，前端 `CN_MIRROR` 指向其中一个，另一个作为人工备份。
